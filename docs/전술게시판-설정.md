# 전술 게시판 켜기 (Supabase)

> ✅ **이 저장소는 2026-08-14 에 이미 켰습니다.** (`src/board/board.js` 에 값이 들어 있습니다.)
> 아래는 **처음부터 다시 켜거나, 다른 프로젝트로 옮길 때** 보는 절차입니다.
>
> 값이 비어 있으면 게시판은 꺼진 채로 배포됩니다 — 게임은 그대로 돌아가고 게시판만 안 보입니다.

무엇을 하는 것인가 — 닉네임과 대전 코드를 남겨 두면, 다른 사람이 목록에서 골라
**그 자리에서 바로 붙어 볼 수 있게** 하는 것입니다. 상대가 접속해 있을 필요가 없습니다.

걸리는 시간은 10분쯤입니다. 카드 등록 같은 건 없습니다(무료 티어).

## 1. 프로젝트 만들기

2. 이름은 아무거나(`kmd26` 등), 지역은 **Northeast Asia (Seoul)** 로 두면 빠릅니다.
3. 데이터베이스 비밀번호를 정합니다 — **이건 어디에도 붙여 넣지 않습니다.** 그냥 보관만 하세요.

## 2. 표와 권한 만들기

왼쪽 메뉴 **SQL Editor** → **New query** 에 아래를 **그대로** 붙여 넣고 **Run**.

```sql
create table if not exists public.plans (
  id         bigint generated always as identity primary key,
  created_at timestamptz not null default now(),
  nick       text    not null check (char_length(nick) between 1 and 12),
  note       text             check (note is null or char_length(note) <= 40),
  team       text    not null check (char_length(team) <= 16),
  code       text    not null check (code ~ '^KM26D1-[A-Za-z0-9_-]{40,80}$'),
  data_hash  text    not null check (char_length(data_hash) <= 24),
  hidden     boolean not null default false,
  unique (code)
);

alter table public.plans enable row level security;

-- 숨기지 않은 것만 누구나 읽는다
create policy "read_visible" on public.plans
  for select using (hidden = false);

-- 누구나 등록은 할 수 있다
create policy "insert_any" on public.plans
  for insert with check (true);

-- ⚠ update·delete 정책은 **만들지 않습니다.**
--   정책이 없으면 anon 키로는 아무도 고치거나 지울 수 없습니다.
```

이 SQL 이 하는 일:

| 장치 | 막아 주는 것 |
|---|---|
| `check (code ~ '^KM26D1-…')` | 대전 코드 모양이 아닌 아무 글이나 올리는 것 |
| `unique (code)` | 같은 라인업을 여러 번 올려 목록을 도배하는 것 |
| `char_length` 제한 | 닉네임·소개에 긴 글을 밀어 넣는 것 |
| update·delete 정책 없음 | 남의 글을 고치거나 지우는 것 |
| `hidden` + 읽기 정책 | 문제되는 글을 **지우지 않고 감추는** 것 |

### 2-1. 듀얼 기록실 표 (`matches`)

경기가 끝나면 **결과 링크**가 여기 쌓입니다 — 누가 누구와 붙어서 어떻게 됐는지가
`record.html`(듀얼 기록실)에 목록으로 뜹니다. 같은 SQL Editor 에 이어서 붙여 넣고 **Run**.

```sql
create table if not exists public.matches (
  id         bigint generated always as identity primary key,
  created_at timestamptz not null default now(),
  url        text    not null check (char_length(url) between 20 and 400),
  fp         text    not null check (char_length(fp) <= 24),
  h_nick     text             check (h_nick is null or char_length(h_nick) between 1 and 12),
  h_team     text    not null check (char_length(h_team) <= 16),
  h_code     text    not null check (h_code ~ '^KM26D1-[A-Za-z0-9_-]{40,80}$'),
  a_nick     text             check (a_nick is null or char_length(a_nick) between 1 and 12),
  a_team     text    not null check (char_length(a_team) <= 16),
  a_code     text    not null check (a_code ~ '^KM26D1-[A-Za-z0-9_-]{40,80}$'),
  hg         int     not null check (hg between 0 and 30),
  ag         int     not null check (ag between 0 and 30),
  data_hash  text    not null check (char_length(data_hash) <= 24),
  hidden     boolean not null default false,
  -- 같은 코드 두 장은 언제나 같은 경기다 → 이게 "같은 경기"의 정의이자 중복 방어다
  unique (h_code, a_code)
);

alter table public.matches enable row level security;

create policy "read_visible" on public.matches
  for select using (hidden = false);

create policy "insert_any" on public.matches
  for insert with check (true);

-- ⚠ 여기도 update·delete 정책은 **만들지 않습니다.**
```

| 장치 | 막아 주는 것 |
|---|---|
| `unique (h_code, a_code)` | **같은 경기가 두 번 올라가는 것.** 코드 두 장이 같으면 결과도 같습니다 |
| `check (… ~ '^KM26D1-…')` | 대전 코드가 아닌 아무 글이나 밀어 넣는 것 |
| `hg`·`ag` 범위 | 말도 안 되는 점수를 적어 넣는 것 |
| `hidden` + 읽기 정책 | 문제되는 기록을 지우지 않고 감추는 것 |

> 💡 **이 표를 안 만들어도 게임은 그대로 돌아갑니다.** 기록실만 "아직 준비되지 않았습니다"로
> 뜨고 경기·게시판은 지금처럼 됩니다. `plans` 만 먼저 만들고 나중에 붙여도 됩니다.

## 3. 주소와 열쇠를 코드에 넣기

### 가장 쉬운 길 — 위쪽 **Connect** 버튼

대시보드 맨 위 **Connect** 를 누르면 **App Frameworks** 탭에 두 줄이 그대로 나옵니다.

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...   (또는 sb_publishable_...)
```

앞쪽이 **URL**, 뒤쪽이 **KEY** 입니다. 이름이 `NEXT_PUBLIC_…` 인 것은 신경 쓰지 마세요 —
"브라우저에 내려가도 되는 값"이라는 뜻이라 우리가 쓰려는 것과 같습니다.

### 메뉴로 찾는 길

| 무엇 | 어디 |
|---|---|
| **URL** | **Project Settings → Data API** 의 `Project URL` |
| **KEY** | **Project Settings → API Keys** |

`API Keys` 화면에는 탭이 둘 있습니다. **어느 쪽을 써도 됩니다.**

- **API Keys** 탭 → `Publishable key` (`sb_publishable_…`) ← 새로 만든 프로젝트의 기본
- **Legacy API Keys** 탭 → `anon` `public` (`eyJhbGciOi…`) ← 예전 방식

찾았으면 `src/board/board.js` 맨 위 두 줄에 붙여 넣습니다.

```js
export const BOARD = {
  URL: "https://xxxxxxxxxxxx.supabase.co",
  KEY: "sb_publishable_...",   // 또는 eyJhbGciOi... (anon public)
};
```

> ⛔ **`Secret key`(`sb_secret_…`) 와 `service_role` 은 절대 넣지 마세요.**
> 그건 모든 권한을 가진 열쇠라, 넣는 순간 누구나 표를 통째로 지울 수 있게 됩니다.
> 넣어야 하는 것은 **Publishable** 또는 **anon public** 입니다.
> 이 둘은 브라우저에 내려가는 것이 정상이고, 그 키로 할 수 있는 일은 2번에서 만든
> 권한 정책이 허락한 것뿐입니다.
>
> **구별법** — `sb_secret_` 이나 `service_role` 이라는 글자가 보이면 그건 아닙니다.
> 화면에서 `Reveal`·`눈 아이콘`을 눌러야 보이는 값도 아닙니다(그건 비밀 쪽입니다).

넣은 뒤 **반드시** 도장을 다시 찍고 올리세요.

```bash
python tools/stamp_version.py
```

## 3-1. 잘 걸렸는지 확인하기

주소와 키를 넣었으면 아래로 한 번 확인해 보세요 (`URL`·`KEY` 를 자기 값으로 바꿔서).

```bash
curl -s -H "apikey: KEY" "URL/rest/v1/plans?select=id&limit=1"
```

`[]` 나 목록이 나오면 읽기까지 잘 된 것입니다. `401` 이면 키가 틀렸고,
`relation "plans" does not exist` 면 2번 SQL 이 안 돌아간 것입니다.

> ⚠ **삭제가 막혔는지 확인할 때 `204` 를 보고 속지 마세요.**
> `delete` 정책이 없으면 **0행이 지워지고**, 그런데도 PostgREST 는 `204 No Content` 를
> 돌려줍니다. "지워졌다"는 뜻이 아닙니다. 진짜로 확인하려면 **지운 뒤 다시 조회해서
> 그 줄이 남아 있는지** 보세요. (이 설정으로 실제 확인했습니다 — 줄이 그대로 남습니다.)

## 4. 관리하기

- **글 감추기** — Table Editor → `plans` → 그 줄의 `hidden` 을 `true` 로.
  지우는 것보다 낫습니다. 지우면 그 사람이 같은 코드로 다시 올릴 수 있습니다.
- **완전히 지우기** — 같은 화면에서 행 삭제.
- **게시판 끄기** — `board.js` 의 `URL`·`KEY` 를 빈 문자열로 되돌리면 화면에서 사라집니다.
