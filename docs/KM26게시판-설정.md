# KM26 갈래 — Supabase 표 만들기

> 이 문서는 **KM26 세이브에서 가져온 명단으로 붙는 갈래**가 쓰는 표를 만듭니다.
> 기본 명단이 쓰는 표(`plans`·`matches`)와는 **완전히 다른 표**입니다 —
> 기존 표는 한 글자도 건드리지 않습니다. 그쪽 설정은 [전술게시판-설정.md](전술게시판-설정.md).
>
> Supabase 프로젝트·API 키는 **이미 만들어 둔 것을 그대로 씁니다.** 새로 만들 것 없습니다.
> `src/board/board.js` 맨 위의 `URL`·`KEY` 두 줄을 KM26 갈래도 함께 씁니다.

---

## 왜 표를 따로 두나

기존 표는 **51자 대전 코드**를 담도록 만들어졌고, 그것을 DB 수준에서 강제합니다.

```sql
code text not null check (code ~ '^KM26D1-[A-Za-z0-9_-]{40,80}$')
unique (code)
```

KM26 갈래는 코드를 만들지 않습니다. 명단이 사람마다 달라서 51자 안에 담기지 않기
때문입니다(선수 스무 명의 능력치까지 담아야 합니다). 대신 **명단 팩을 통째로 올립니다.**
모양이 다르므로 기존 표에는 들어갈 수 없고, 넣으려 하면 Supabase 가 거부합니다.

| | 기본 갈래 (`plans`) | KM26 갈래 (`plans_km`) |
|---|---|---|
| 무엇을 담나 | 51자 코드 | 명단 팩 (JSON · 약 15KB) |
| 같은 글 판정 | `unique (code)` | `unique (sig)` |
| 기록실이 가리키는 것 | 결과 링크(코드 두 장) | 글 두 개 (`h_plan`·`a_plan`) |
| 다시 보기 | 코드 두 장으로 재계산 | 글 두 개로 재계산 |

---

## 1. 표와 권한 만들기

왼쪽 메뉴 **SQL Editor** → **New query** 에 아래를 **그대로** 붙여 넣고 **Run**.

```sql
-- ── KM26 갈래 전술 게시판 ──────────────────────────────────────
create table if not exists public.plans_km (
  id         bigint generated always as identity primary key,
  created_at timestamptz not null default now(),
  nick       text    not null check (char_length(nick) between 1 and 12),
  note       text             check (note is null or char_length(note) <= 40),
  team       text    not null check (char_length(team) <= 16),
  season     int              check (season is null or season between 2000 and 2100),
  -- 같은 라인업 + 같은 명단이면 같은 값이 나온다. 이게 "같은 글"의 정의다
  -- ⚠ 화면이 넣는 것은 **16자리로 접은 열쇠**다(`kmsave.js` 의 `sigKey`).
  --   사람이 읽는 지문은 244자라 이 칸에 안 들어간다 — 잘라 넣으면 다시 못 찾는다.
  sig        text    not null check (char_length(sig) between 8 and 64),
  -- 명단 팩(JSON). 선발 11 + 교체 9 = 스무 명의 능력치까지 들어 있다
  pack       text    not null check (char_length(pack) between 200 and 200000),
  hidden     boolean not null default false,
  unique (sig)
);

alter table public.plans_km enable row level security;

create policy "read_visible" on public.plans_km
  for select using (hidden = false);

create policy "insert_any" on public.plans_km
  for insert with check (true);

-- ⚠ update·delete 정책은 **만들지 않습니다.**
--   정책이 없으면 anon 키로는 아무도 고치거나 지울 수 없습니다.
```

이어서 기록실 표도 같은 창에 붙여 넣고 **Run**.

```sql
-- ── KM26 갈래 듀얼 기록실 ──────────────────────────────────────
create table if not exists public.matches_km (
  id         bigint generated always as identity primary key,
  created_at timestamptz not null default now(),
  fp         text    not null check (char_length(fp) <= 24),
  -- 결과 링크가 없다. 대신 붙은 두 글을 가리킨다 — 그 둘이면 경기를 다시 만들 수 있다
  h_plan     bigint  not null references public.plans_km(id),
  a_plan     bigint  not null references public.plans_km(id),
  h_nick     text             check (h_nick is null or char_length(h_nick) between 1 and 12),
  h_team     text    not null check (char_length(h_team) <= 16),
  a_nick     text             check (a_nick is null or char_length(a_nick) between 1 and 12),
  a_team     text    not null check (char_length(a_team) <= 16),
  hg         int     not null check (hg between 0 and 30),
  ag         int     not null check (ag between 0 and 30),
  hidden     boolean not null default false,
  -- 같은 글 두 개는 언제나 같은 경기다 → 중복 방어이자 "같은 경기"의 정의
  unique (h_plan, a_plan)
);

alter table public.matches_km enable row level security;

create policy "read_visible" on public.matches_km
  for select using (hidden = false);

create policy "insert_any" on public.matches_km
  for insert with check (true);
```

### 무엇을 막고 있나

| 장치 | 막는 것 |
|---|---|
| `unique (sig)` | 같은 라인업·명단을 여러 번 올려 목록을 도배하는 것 |
| `pack` 길이 상한 200,000자 | 거대한 파일을 밀어 넣어 용량을 태우는 것 |
| `char_length` 제한 | 닉네임·소개에 긴 글을 밀어 넣는 것 |
| update·delete 정책 없음 | 남의 글을 고치거나 지우는 것 |
| `hidden` + 읽기 정책 | 문제되는 글을 **지우지 않고 감추는** 것 |
| `references plans_km(id)` | 없는 글을 가리키는 기록이 남는 것 |
| `unique (h_plan, a_plan)` | 같은 경기를 여러 번 올리는 것 |

## 2. 용량은 괜찮은가

한 글에 **약 15KB** 입니다 (실측: 안양 스무 명 · 능력치 40종 · 능숙도 17자리).

| | 크기 |
|---|---|
| 명단 전체 38명 | 30.6 KB |
| **게시판용 — 스무 명만, 값이 0인 능숙도 생략** | **15.0 KB** |

Supabase 무료 티어는 데이터베이스 500MB 이므로 글 3만 건까지 들어갑니다.
오픈베타에서 그만큼 쌓일 일은 없습니다.

> ⚠ **겹치는 능력치(`pace`/`pac` 등)를 덜어 내면 안 됩니다.** 기본 명단에서는 짝이
> 전부 같지만 **KM26 세이브에서는 다릅니다** — 시즌 중 한쪽만 갱신된 선수가 있습니다
> (실측 스무 명 중 48곳). 덜어 냈다가 되살리면 능력치가 조용히 달라집니다.

## 3. 잘 됐는지 보기

**Table Editor** 에 `plans_km` · `matches_km` 두 표가 보이면 됩니다.
`plans_km` 의 `pack` 칸은 아주 긴 글이라 화면에서는 잘려 보입니다 — 정상입니다.

게임 쪽에서는 KM26 라인업 화면에서 명단을 불러온 뒤 **게시판에 올리기**를 눌러 보세요.
표가 없으면 화면에 "KM26 게시판이 아직 준비되지 않았습니다" 라고만 뜨고,
**게임의 나머지는 그대로 돌아갑니다.**

---

## 4. 문제 글 감추기

지우지 않고 감춥니다 — 지우면 그 글을 가리키는 기록까지 깨집니다.

```sql
update public.plans_km   set hidden = true where id = 123;
update public.matches_km set hidden = true where id = 456;
```

`plans_km` 의 글을 감추면 **그 글이 낀 기록은 다시 보기를 할 수 없습니다**
(명단을 못 읽으니 경기를 다시 만들 수 없습니다). 기록도 함께 감추는 편이 낫습니다.

```sql
update public.matches_km set hidden = true
 where h_plan = 123 or a_plan = 123;
```
